## Phases

### Phase 39: Auth-Separaatio

**Goal**: Consumer- ja business-puolen auth-sessiot ovat täysin toisistaan riippumattomia — business-reitit käyttävät `sb-biz-*`-cookieta, consumer-reitit käyttävät normaalia `sb-*`-cookieta, ja molemmat voivat olla aktiivisina samanaikaisesti
**Depends on**: Phase 38 (v1.8 complete)
**Requirements**: AUTHSEP-01, AUTHSEP-02, AUTHSEP-03, AUTHSEP-04, AUTHSEP-05, AUTHSEP-06, AUTHSEP-07
**Plans**: 4 plans

Plans:
- [x] 39-01-PLAN.md — Create lib/supabase-business.ts (sb-biz-* namespace clients)
- [x] 39-02-PLAN.md — Middleware path-conditional refresh + i18n strings
- [x] 39-03-PLAN.md — /business/kirjaudu login page
- [x] 39-04-PLAN.md — Migrate all /business/* pages to business client

**Details:**
`lib/supabase-business.ts` exports `createBusinessBrowserClient()` (singleton, `sb-biz-*` cookies) and `createBusinessServerClient()` (SSR-safe, `sb-biz-*` cookies). `middleware.ts` branches on `isBusiness = pathname.startsWith('/business')`: business branch refreshes `sb-biz-*` session and guards unauthorized routes to `/business/kirjaudu`; consumer branch refreshes `sb-*` session without guard. `/business/kirjaudu` is a dedicated business login page (glassmorphism, next-intl, `createBusinessBrowserClient`). All `/business/*` RSC layouts and pages + all `/api/business/*` Route Handlers migrated to use `createBusinessServerClient(cookies())` or JWT verification via `supabaseAdmin.auth.getUser(token)`.

## Milestone Summary

**Key Decisions:**

- `sb-biz-*` cookie namespace (not a separate Supabase project) — one project, two namespaces sufficient; avoids operational overhead
- Middleware constructs clients inline (not via `createBusinessServerClient`) — Edge Runtime has no `ReadonlyRequestCookies`; must use `request.cookies` directly
- `OnboardingMode` + `EditMode` as private sub-components inside `WizardInner.tsx` — not separate exported components, cleaner API surface
- Business auth uses same Supabase Auth project — role derived from `business_accounts` table, not `auth.users.metadata`

**Issues Resolved:**

- Consumer auth and business auth sessions were previously shared — same cookie namespace caused interference
- `OnboardingWizardInner` and `EditWizardInner` were near-duplicates with diverged logic — consolidated into single WizardInner

**Issues Deferred:**

- CLEAN-01 test account deletion requires manual `supabase db push` — migration created but not executed (no test data in production)
- CR-01 (business/[id]/page.tsx ownership check) and CR-02 (submit route paikka_id filter) applied as post-review fixes on 2026-06-12

**Technical Debt Incurred:**

- None — this milestone was specifically a debt-reduction milestone
