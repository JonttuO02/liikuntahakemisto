<objective>
Implement D-07: auto-resubmit-on-save. When a rejected venue's section is saved through `app/api/business/update-paikka/route.ts`, the handler transitions `business_paikka_links.claim_status` from `rejected` back to `pending` and clears `rejection_reason` as a server-side side effect — replacing the explicit `/api/business/reapply` step (which Plan 05 removes). The 24h reapply cooldown is deliberately NOT ported (D-15). This is the backend half of PREV-05's "purely visual" guarantee: the dashboard has no explicit resubmit action; status flips happen only on a real save.

Purpose: remove one user-facing step while keeping the status transition trustworthy (server-derived, never client-supplied) and concurrency-safe.
Output: the new conditional branch in `update-paikka/route.ts` plus extended Vitest coverage.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API (update-paikka) | Authenticated business user POSTs a section save; the request body is untrusted input |
| authenticated user → own claim row | The status transition must stay scoped to the caller's own business_account_id + paikka_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-63-01 | Tampering / Elevation of Privilege | update-paikka claim_status transition | high | mitigate | Decision to flip is derived from the server-side `linkRow.claim_status` fetched via the already-authenticated `business_account_id`/`paikka_id`; `claim_status` is never read from the request body. Test case (c) asserts a client-supplied body `claim_status` is ignored. |
| T-63-02 | Denial of Service (notification/queue spam) | Concurrent duplicate section saves both flipping rejected→pending | medium | mitigate | The flip UPDATE carries `.eq('claim_status', 'rejected')` so only the first racing request performs the transition (same guard as reapply/route.ts); no admin-notification email is sent from this path, so no email spam vector is introduced |
| T-63-03 | Repudiation | Loss of the 24h anti-flood cooldown (D-15) | low | accept | Cooldown deliberately dropped per D-15 (no real users yet; a per-section save requires deliberate edit effort). Documented as an accepted product decision, not a silent omission. |
</threat_model>
