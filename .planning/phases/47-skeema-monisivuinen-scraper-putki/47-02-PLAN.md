<objective>
Extract the SSRF validation logic currently inlined in `route.ts` into a shared, reusable `isUrlSafe(url)` validator (D-08), and build a `fetchWithSsrfGuard` wrapper that switches all fetches to `redirect: 'manual'` and re-validates every redirect `Location` header against the same validator with a 2-hop cap (D-09/D-10). These utilities are the security foundation that the scraper (Plan 47-03) and route (Plan 47-05) will call on every outbound fetch.

Purpose: SCRAP-07 — the current pipeline only validates the user-submitted entry URL. A legitimate-looking homepage can link to (or 302-redirect to) a private IP, bypassing the entry check. Re-validating every discovered link and every redirect hop closes that SSRF-via-redirect vector.
Output: Two new server-only utility modules plus a unit test for both.
</objective>

| T-47-04 | Denial of Service | redirect loop | mitigate | 2-hop cap aborts before unbounded redirect chains |
| T-47-05 | Information Disclosure | SSRF via DNS rebinding (hostname resolves public at check, private at fetch) | accept | Carried forward as P45-DNS; hostname-string check is pre-DNS-resolution. Explicitly out of scope per RESEARCH.md; documented, not silently ignored |
