<objective>
Add a single additive migration that reshapes `business_branding` for plural branding data and per-venue scoping: four new columns (BRDDB-03), a `paikka_id` column with backfill, and a re-keyed composite UNIQUE constraint (BRDDB-05). Verify (not re-implement) the already-shipped `logo_type` CHECK constraint fix (BRDDB-04). Push the migration to the live Supabase database so downstream route/analyzer code (Plan 47-05) can write the new shape without false-positive build/type passes.

Purpose: The current `UNIQUE(business_account_id)` silently overwrites a sibling venue's branding when one business account manages multiple venues; the schema also lacks columns for the plural logo/color/image data Phase 48 will let users pick from.
Output: One new migration file, pushed to the live database, with verification evidence for all three BRDDB requirements.
</objective>
