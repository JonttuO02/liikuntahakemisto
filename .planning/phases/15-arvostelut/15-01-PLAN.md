<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Supabase `reviews` table (writes) | Untrusted user submits rating/text/anonymity/date/crowd; RLS + DB CHECK constraints enforce isolation and value safety |
| Browser → Supabase `reviews` table (reads) | Public read by design (REVIEW-04); only sanitised columns are exposed, never raw `user_id` |
| Developer machine → Supabase project (migration push) | Schema-level change applied by trusted operator via CLI or dashboard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Tampering | reviews INSERT/UPDATE — cross-user write | mitigate | RLS policies `Users can insert own review` and `Users can update own review` enforce `auth.uid() = user_id` via WITH CHECK |
| T-15-02 | Information Disclosure | reviews public read — author identity leak | mitigate | `reviewer_name text` column stores email prefix at write time (Plan 03); `resolveDisplayName` (Task 1) returns 'Anonyymi' when `is_anonymous=true`; `user_id` is never rendered |
| T-15-03 | Tampering | duplicate reviews via parallel writes | mitigate | DB-level `UNIQUE(user_id, paikka_id)` constraint — second insert rejected with 23505, second upsert routed to UPDATE path |
| T-15-04 | Tampering | future visit dates injected via API | mitigate | `max={today}` enforced on `<input type="date">` in Plan 03; `visit_date date` is nullable and informational |
| T-15-SC | Tampering | npm/pip/cargo installs | accept | No new packages added in Phase 15 — RESEARCH.md confirms zero new dependencies |
</threat_model>
