    Create `app/api/business/access-request/approve/route.ts` exporting async `POST(request: Request)`.

    1. JWT verify (token from Authorization header, `supabaseAdmin.auth.getUser`, 401 on failure).
    2. Parse `request_id` from body via `parseInt` + `isNaN` guard -> 400.
    3. Fetch the request row from `business_access_requests` by `id` (`select('id, requester_id, paikka_id, status').eq('id', requestId).maybeSingle()`); 404 if not found.
    4. Owner-authorization check (venue-scoped, Assumption A3 / D-04): confirm the caller `user.id` is the approved owner of the request's `paikka_id` — i.e. there exists a `business_paikka_links` row with `paikka_id = row.paikka_id AND claim_status = 'approved' AND business_account_id = user.id`, AND that caller's `business_accounts.role = 'owner'`. If not -> 403. Do NOT allow any company-wide owner to approve a venue they don't manage.
    5. Non-pending guard: if `row.status !== 'pending'` -> 409.
    6. Atomic transition: `supabaseAdmin.from('business_access_requests').update({ status: 'approved', updated_at: new Date().toISOString() }, { count: 'exact' }).eq('id', requestId).eq('status', 'pending')`. 500 on updateError; if `!count` -> 409 "already processed". This guard is the concurrency control — never SELECT-then-unconditional-UPDATE.
    7. Grant access (all via supabaseAdmin, bypasses RLS — Pitfall 3): resolve the inviting venue's company_id (from the owner's `business_accounts.company_id` for the request's paikka), then UPDATE the requester's `business_accounts` SET `company_id = <that company>, role = 'member'` WHERE `user_id = row.requester_id`; and INSERT a `business_paikka_links` row `{ business_account_id: row.requester_id, paikka_id: row.paikka_id, claim_status: 'approved', link_type: 'claim' }`. This INSERT MUST use supabaseAdmin (the owner is inserting on behalf of the requester; the RLS INSERT policy `auth.uid() = business_account_id` would reject it otherwise).
    8. Non-critical requester email (try/catch, `[access-request/approve]` prefix): `getUserById(row.requester_id)` for email, fetch venue `nimi`, call `sendAccessRequestDecisionEmail(requesterEmail, { venueName, approved: true })`. Still return `{ ok: true }` even on email failure.
