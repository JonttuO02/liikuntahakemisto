  <behavior>
    First render (cache miss):
      1. aiTeksti state = null — widget text area renders empty (no text visible)
      2. useEffect fires after mount: check sessionStorage["saasuositus-YYYY-MM-DD"]
      3. Key not found → fetch('/api/saasuositus')
      4. On success: setAiTeksti(data.text), sessionStorage.setItem(key, data.text)
      5. Widget re-renders with AI text

    Subsequent renders (cache hit, same day):
      1. aiTeksti state = null — widget text area renders empty momentarily
      2. useEffect fires: sessionStorage key found
      3. setAiTeksti(cached) — no fetch; text appears immediately after mount
      4. Widget re-renders with cached AI text

    Failure paths:
      - Route Handler always returns HTTP 200 with fallback text (handled in 05-01) — covers Claude/Open-Meteo failures
      - If fetch itself throws (network down, DNS failure): .catch() calls getTimeBasedFallback(), sets aiTeksti, caches result in sessionStorage — same-day reloads show cached fallback, no retry
      - sessionStorage read/write errors: wrapped in try/catch, silent

    Weather display (unchanged):
      - saa state is set by the existing Open-Meteo useEffect (lines 82-87 of original)
      - Do NOT remove or modify the saa useEffect — it provides weather emoji + temp display
  </behavior>
