<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated business user → business_accounts row (own row) | A logged-in business user can UPDATE their own business_accounts row via the existing own-row RLS policy — untrusted with respect to the new privileged columns |
| authenticated user → companies / business_paikka_links via RLS | Row access is mediated by current_company_id(); a misconfigured policy could leak cross-company data |
| SECURITY DEFINER function → tables it reads | current_company_id() runs with owner privileges, bypassing RLS internally |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-59-01 | Tampering | Backfill join (companies ↔ business_accounts) | mitigate | ROW_NUMBER() CTE guarantees 1:1 correspondence even with duplicate company_name; `_audit/59-backfill-verification.sql` section 3 verifies every row's name match before production (Pitfall 1) |
| T-59-02 | Denial of Service | current_company_id() EXECUTE grant | mitigate | Explicit `GRANT EXECUTE ... TO authenticated` in the migration; absence silently denies all RLS-gated access (Pitfall 2) — verified during staging gate |
| T-59-03 | Information Disclosure | New companies table RLS | mitigate | `ENABLE ROW LEVEL SECURITY` + SELECT policy `USING (id = current_company_id())`; no client write policy (CLAUDE.md anon-read-only) (Pitfall 3) |
| T-59-04 | Elevation of Privilege | business_accounts.role / company_id self-update | mitigate | `REVOKE UPDATE (role, company_id) ON business_accounts FROM authenticated` — prevents a member self-promoting to owner via the existing own-row UPDATE policy (Pattern 3) |
| T-59-05 | Tampering | current_company_id() search_path hijack | mitigate | `SET search_path = public` pinned in the function definition (matches set_business_managed_on_approval precedent) |
| T-59-06 | Information Disclosure | Incompletely-scoped RLS rewrite (cross-company leak) | mitigate | Comment block enumerates every existing policy on business_accounts/business_paikka_links marked keep-as-is or rewritten; D-14 keeps business_paikka_links SELECT self-scoped, deferring company-wide widening to Phase 60/64 |
| T-59-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase — pure SQL migration, zero new dependencies (RESEARCH.md Package Legitimacy Audit: N/A) |
</threat_model>
