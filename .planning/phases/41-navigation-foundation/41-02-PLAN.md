<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → RSC kirjaudu/page.tsx | Server reads sb-biz-* session cookie to determine if user is authenticated before rendering |
| RSC → Supabase Auth | createBusinessServerClient reads the sb-biz-* cookie; getUser() validates the JWT server-side |
| BusinessLayout RSC → BusinessNav client | RSC/client boundary; layout stays server, BusinessNav is client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-04 | Information Disclosure | kirjaudu/page.tsx RSC redirect | mitigate | Server-side session check via createBusinessServerClient(cookies()).auth.getUser() fires before any client rendering — authenticated user never sees the login form (no flash) |
| T-41-05 | Elevation of Privilege | app/business/layout.tsx | accept | Layout is RSC; BusinessNav is rendered as client child — no privilege boundary crossed; middleware guards the route tree independently |
| T-41-06 | Spoofing | BusinessNav sign-out | accept | Sign-out calls Supabase server-side token revocation via createBusinessBrowserClient; sb-biz-* cookie cleared; consumer session unaffected by design (separate cookie namespace) |
| T-41-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan; all dependencies verified in package.json |
</threat_model>
