From PATTERNS.md — UploadDropZone HTML5 drag pattern:
```tsx
function handleDragOver(e: React.DragEvent) { e.preventDefault(); setIsDragging(true) }
function handleDragLeave() { setIsDragging(false) }
function handleDrop(e: React.DragEvent) {
  e.preventDefault(); setIsDragging(false)
  const files = Array.from(e.dataTransfer.files).filter(f => f.type.startsWith('image/'))
  onFilesSelected(files)
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Storage (business-media bucket) | anon client with active session; RLS policy checks auth.uid() ownership of the storage path |
| StepMediat → /api/business/onboarding/save-step | JWT Authorization header; save-step verifies token before writing to DB |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-07-01 | Tampering | Storage path construction | mitigate | Path built from businessAccountId + paikkaId (both from verified session/component props, not user input); no user-supplied path segments |
| T-34-07-02 | Tampering | supabaseAdmin in client component | mitigate | StepMediat uses createBrowserSupabase() for all Supabase calls; supabaseAdmin is never imported in any 'use client' file (Pitfall 2) |
| T-34-07-03 | Denial of Service | oversized file bypass client check | accept | File size checked client-side in UploadDropZone via file.size <= maxFileSizeMB * 1024 * 1024 before upload; Supabase Storage enforces its own size limits |
| T-34-07-04 | Tampering | MIME type spoofing via file extension | accept | accept="image/*" on file input + file.type.startsWith('image/') filter; browser enforces MIME for drag-and-drop; Storage serves with content-type from upload — no server-side execution risk for images |
| T-34-07-SC | Tampering | npm (no new packages) | accept | No new packages; lucide-react Upload icon already available |
</threat_model>
