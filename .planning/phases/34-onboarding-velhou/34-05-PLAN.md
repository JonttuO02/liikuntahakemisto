<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/business/onboarding/save-step | JWT in Authorization header; user identity extracted from token — body is untrusted |
| client → /api/business/onboarding/submit | JWT + business_paikka_links ownership check before liikuntapaikat write |
| supabaseAdmin → DB | Service role bypasses RLS; user.id from verified JWT gates all operations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-05-01 | Elevation of Privilege | submit → liikuntapaikat write | mitigate | business_paikka_links ownership verified (user.id + paikka_id) before any UPDATE; 403 returned if link absent |
| T-34-05-02 | Tampering | body.business_account_id in save-step | mitigate | business_account_id in UPSERT always set to user.id from verified JWT; body value ignored |
| T-34-05-03 | Tampering | arbitrary paikka_id in save-step | mitigate | save-step only UPSERTs the draft — no liikuntapaikat writes; submit handler verifies paikka_id via business_paikka_links before writing to liikuntapaikat |
| T-34-05-04 | Denial of Service | oversized JSONB in save-step body | accept | Supabase enforces 8KB row limit; Next.js default 4MB body limit; no additional check needed for JSONB wizard data |
| T-34-05-SC | Tampering | npm/pip/cargo installs | accept | No new packages in this plan |
</threat_model>
