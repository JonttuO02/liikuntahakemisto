## Key Technical Constraint (discovered this session)

CSS `clip-path` clips the painted output of an element **including all borders, box-shadow, and outline**. These properties cannot follow the bump shape.

The only standard CSS approach that follows a clip-path shape is `filter: drop-shadow()` — it applies AFTER clip-path. But it renders OUTSIDE the element (between the glass surface and the map), creating a shadow rather than an edge color change.

Options that were NOT tried:
1. **Architectural change**: `<motion.div clip-path wrapper> <div className="glass" style={{border: ...}}> </div> </motion.div>` — the inner glass div's rectangular border would be partially visible where the clip-path intersects y=0 (bump top). Only the bump dome apex would show a thin arc border. Not a full solution but might add definition to the bump's topmost point.
2. **Shoulder-only inner border**: absolutely-positioned 1px div at `top: TAB_H` inside the sheet — creates a visible horizontal line at the flat shoulder, inside the clip region. Combined with drop-shadow for the bump dome.
3. **Design direction change**: simplify the top shape (remove bump, use `rounded-t-3xl` like standard bottom sheets) — then normal glass borders work. Loses the distinctive bump but gains easy visual definition.
4. **Make glass more opaque**: increase the glass background opacity to 0.95–1.0 — stronger contrast against map creates natural visual edge.
