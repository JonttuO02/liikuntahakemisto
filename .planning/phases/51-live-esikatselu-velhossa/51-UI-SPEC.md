## Interaction & Layout Contract (phase-specific — supplements template)

### Breakpoint: desktop split-view vs mobile toggle
- **`lg:` (1024px)** is the split-view activation breakpoint. Rationale: the form column is a fixed `max-w-xl` (576px); the preview column needs ~320-360px plus a 24px gap plus outer padding to avoid a cramped squeeze — `lg:` is the first Tailwind breakpoint with enough viewport width for both, and it's the standard "introduce a sidebar" breakpoint already implicit in this codebase's Tailwind v3 config (no custom breakpoints declared in `tailwind.config.ts`, so defaults apply: `sm`=640, `md`=768, `lg`=1024, `xl`=1280).
- Below `lg:` (including `md:` tablet), the layout falls back to the mobile segmented-toggle pattern (D-08) — there is no intermediate "narrow 2-column" state, per D-06's explicit instruction to avoid a cramped squeeze.

### Desktop split-view (`lg:` and above)
```
<div className="flex gap-6 items-start justify-center">
  <div className="w-full max-w-xl">{/* existing form column — ProgressBar + step content, unchanged width */}</div>
  <div className="hidden lg:flex flex-col gap-4 w-[360px] flex-shrink-0 sticky top-6">
    <div className="flex flex-col gap-2">
      <span className="text-[10px] font-bold uppercase tracking-widest text-[rgba(17,17,17,0.45)]">
        {t('previewLabelCallout')}
      </span>
      <CalloutCard p={livePreviewPaikka} brandColor={brandColor} accentColor={accentColor} />
    </div>
    <div className="flex flex-col gap-2">
      <span className="text-[10px] font-bold uppercase tracking-widest text-[rgba(17,17,17,0.45)]">
        {t('previewLabelDiag')}
      </span>
      <DiagonaalKortti paikka={livePreviewPaikka} brandColor={brandColor} accentColor={accentColor} />
    </div>
  </div>
</div>
```
- Preview column width: **360px fixed** (`w-[360px] flex-shrink-0`) — wide enough that `DiagonaalKortti`'s `h-36` card and `CalloutCard`'s 160px-wide card both render at their natural/near-natural size without text truncation pressure, narrower than the 576px form column so the eye reads form-first.
- Gap between form and preview column: **24px** (`gap-6`).
- Gap between the two stacked cards inside the preview column: **16px** (`gap-4` — slightly more breathing room than the 8px used between a card's *internal* label and card, since these are two distinct card "sections", matching `StepEsikatselu.tsx`'s existing `gap-6` between its three preview sections scaled down slightly because this column is narrower and has only 2 cards, not 3).
- The preview column is `sticky top-6` so it stays visible while the (potentially taller) form column scrolls — there is no existing sticky precedent in this codebase, but it directly serves LIVEPREV-02 ("visible side-by-side with the step currently being edited") since steps vary significantly in height (StepHinnasto's repeatable rows vs StepYhteystiedot's short form).
- `CalloutCard` is listed first (top), `DiagonaalKortti` second (bottom) — same order as `StepEsikatselu.tsx`'s existing static preview, preserving an already-established visual hierarchy (map-pin card first, list card second).
- No outer `.glass` wrapper around the preview column — the two cards already carry their own `.glass` surface; wrapping them again would double the glassmorphism effect and look heavier than intended. The column is a plain flex container directly on the white page background.

### Mobile segmented control (below `lg:`)
```
<div className="glass rounded-full p-1 flex w-full max-w-xl mx-auto mb-4">
  <button className={`flex-1 h-9 rounded-full text-sm font-bold flex items-center justify-center gap-1.5 [transition:background-color_150ms_var(--ease-out),color_150ms_var(--ease-out)] ${
    activeView === 'edit' ? 'bg-[#111111] text-white' : 'text-[rgba(17,17,17,0.45)]'
  }`}>
    <Pencil className="w-3.5 h-3.5" /> {t('previewToggleEdit')}
  </button>
  <button className={`flex-1 h-9 rounded-full text-sm font-bold flex items-center justify-center gap-1.5 [transition:background-color_150ms_var(--ease-out),color_150ms_var(--ease-out)] ${
    activeView === 'preview' ? 'bg-[#111111] text-white' : 'text-[rgba(17,17,17,0.45)]'
  }`}>
    <Eye className="w-3.5 h-3.5" /> {t('previewToggleLive')}
  </button>
</div>
```
- Visual base: `.glass rounded-full p-1` track (a pill-shaped glass surface, distinct from `ProgressBar`'s rounded-2xl card and from the EditMode tab bar's plain flex-of-pills-on-transparent-background) — chosen because this is a binary view-switch (closer to an iOS segmented control) rather than a multi-step navigator like `ProgressBar`/the tab bar, so a single enclosing track communicates "exactly one of these two is active" more clearly than free-floating pills.
- Active segment: `bg-[#111111] text-white` — identical token to the EditMode tab bar's active state (`WizardInner.tsx` line 379) and `ProgressBar`'s current-step circle, keeping the accent-color contract consistent project-wide.
- Inactive segment: `text-[rgba(17,17,17,0.45)]` on transparent (no background) — matches the EditMode tab bar's inactive state exactly.
- Icons: `Pencil` (edit) / `Eye` (preview) at `w-3.5 h-3.5` (14px), from `lucide-react` (already the project's icon library — see `DiagonaalKortti.tsx`'s `MapPin`, `BookmarkCheck` imports). Icons are optional polish, not load-bearing — if omitted, label-only pills are an acceptable fallback that still satisfies D-07's "visually consistent with existing tab-bar styling" requirement.
- Width: full-width pill row (`w-full max-w-xl mx-auto`), matching the form column's own `max-w-xl`, sitting directly above the step/tab content exactly as D-07 specifies ("sits above the step/tab content").
- Tap feedback: `whileTap={{ scale: 0.95 }}` on each segment button — matches CLAUDE.md's documented filter-button rule ("Filter buttons: whileTap scale 0.95 only. No hover scale").
- Below `lg:`, when `activeView === 'preview'`, the preview column (same `CalloutCard`/`DiagonaalKortti` stack as desktop, same 16px internal gap) replaces the form content area entirely — not an overlay, a full content swap, using the existing `AnimatePresence mode="wait"` crossfade pattern already wrapping step content in `WizardInner.tsx` (opacity-only, `duration: 0.2`, per CLAUDE.md's View Transitions rule). The Muokkaa/Esikatselu toggle itself stays mounted and visible regardless of which side is active.
- **Reset on step change (D-08):** `activeView` state resets to `'edit'` every time the wizard's `step` (onboarding) or `currentStep` (EditMode tab) value changes — implemented as a `useEffect` keyed on that step/tab value, not persisted in the shared preview context (the toggle's view-mode is local UI state, separate from the live-preview *data* context).

### Debounced vs instant update feedback (D-04/D-05)
- **No micro-transition or visual "updating" indicator is added.** Per CLAUDE.md's animation rules ("No animate for decoration", "Avoid animating height: auto"), and because `CalloutCard`/`DiagonaalKortti` already have their own internal motion (character-stagger name animation, hover scale) that would visually compete with any additional "just updated" flash — a flat re-render is the correct, minimal-surprise behavior.
- Debounced text fields (D-04, ~250-300ms): the preview pane simply re-renders with the new value once the debounce timer fires — same as any other React state update, no fade/pulse/highlight.
- Instant fields (D-05 — logo/photo blob URLs, color selection): same flat re-render, just without the debounce delay before it fires.
- Exception: if a field debounce causes `CalloutCard`'s internal price-marquee (`useOverflowMarquee`) to re-measure mid-typing in a way that's visually jittery, that is an implementation/QA concern for the executor to verify against existing marquee behavior — not a new design requirement for this phase.
