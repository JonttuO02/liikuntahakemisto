## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-64-05 | Tampering | self-removal via API | high | mitigate | Server-side `target_user_id === user.id` hard-block returns 400 before any DB access, independent of the UI-disabled control (D-12/D-14, Pitfall 9) |
| T-64-06 | Elevation of Privilege / IDOR | remove authorization | high | mitigate | Venue-scoped owner check (approved link for the specific `paikka_id` AND `role==='owner'`) — an owner of Venue A cannot remove a member from Venue B (Pitfall 8) |
| T-64-07 | Spoofing | bearer token | high | mitigate | `supabaseAdmin.auth.getUser(token)`; `user.id` never taken from body |
| T-64-08 | Tampering | claim_status CHECK | medium | mitigate | Literal DELETE (not UPDATE to a non-existent 'removed' status) avoids a runtime CHECK-violation 500 and matches D-11 no-undo (Pitfall 4) |
| T-64-09 | Tampering | concurrent double-remove | low | mitigate | `{ count: 'exact' }` guard → second concurrent removal returns 404, no double side effect |
