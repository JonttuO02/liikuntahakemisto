    Create app/sw.ts as a TypeScript file (not .js). This file is compiled by the withSerwist webpack plugin to public/sw.js.

    Imports required (all from "serwist" or "@serwist/next/worker"):
    - `defaultCache` from "@serwist/next/worker"
    - `PrecacheEntry`, `SerwistGlobalConfig` types from "serwist"
    - `CacheFirst`, `ExpirationPlugin`, `NetworkFirst`, `Serwist`, `StaleWhileRevalidate` from "serwist"

    Global declarations (required for TypeScript to recognise SW globals and __SW_MANIFEST):
    - `declare global { interface WorkerGlobalScope extends SerwistGlobalConfig { __SW_MANIFEST: (PrecacheEntry | string)[] | undefined } }`
    - `declare const self: ServiceWorkerGlobalScope`

    Define a `customStrategies` array with three entries in this order (order matters — first match wins):

    Entry 1 — RSC prefetch (link hover, highest priority):
    - matcher: sameOrigin AND request.headers.get("RSC") === "1" AND request.headers.get("Next-Router-Prefetch") === "1" AND pathname does NOT start with "/api/"
    - handler: new StaleWhileRevalidate({ cacheName: "pages-rsc-prefetch", plugins: [ExpirationPlugin({ maxEntries: 32, maxAgeSeconds: 86400, maxAgeFrom: "last-used" })] })

    Entry 2 — RSC navigation (link click):
    - matcher: sameOrigin AND request.headers.get("RSC") === "1" AND pathname does NOT start with "/api/"
    - handler: new StaleWhileRevalidate({ cacheName: "pages-rsc", plugins: [ExpirationPlugin({ maxEntries: 32, maxAgeSeconds: 86400, maxAgeFrom: "last-used" })] })

    Entry 3 — listing page document (D-05, D-06, D-07):
    - matcher: sameOrigin AND url.pathname === "/" AND url.searchParams.get("nakyma") === "lista"
    - handler: new NetworkFirst({ cacheName: "listing-page", networkTimeoutSeconds: 10, plugins: [ExpirationPlugin({ maxEntries: 4, maxAgeSeconds: 86400, maxAgeFrom: "last-fetched" })] })

    Construct the Serwist instance with:
    - precacheEntries: self.__SW_MANIFEST
    - precacheOptions: { cleanupOutdatedCaches: true, ignoreURLParametersMatching: [/^_rsc$/] }
    - skipWaiting: true
    - clientsClaim: true
    - navigationPreload: true
    - runtimeCaching: [...customStrategies, ...defaultCache]
    - fallbacks: { entries: [{ url: "/offline", matcher({ request }) { return request.destination === "document" } }] }

    Call serwist.addEventListeners() at the bottom.

    Important: Do NOT cache /api/ routes anywhere — no matcher should match paths starting with /api/. Supabase auth cookies flow through /api/ and must never be cached (RESEARCH.md Pitfall 6, Security Domain).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Service Worker | SW intercepts all same-origin fetch requests |
| Service Worker → Network | SW passes through uncached requests |
| Service Worker → Cache Storage | SW reads/writes cached responses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-03 | Information Disclosure | SW caching Set-Cookie responses | mitigate | /api/ routes excluded from all runtimeCaching matchers; listing page is publicly accessible (no auth gate, no Set-Cookie for anon users per RESEARCH.md Pitfall 6) |
| T-11-04 | Tampering | SW scope too broad | accept | SW defaults to root /; all routes are same-origin; no cross-origin assets served |
| T-11-05 | Information Disclosure | Stale auth state served from cache | mitigate | skipWaiting + clientsClaim activates new SW immediately; cleanupOutdatedCaches removes stale entries; 24h TTL on listing-page cache |
| T-11-06 | Denial of Service | SW active in dev poisoning hot reload | mitigate | disable: process.env.NODE_ENV === "development" (D-02 locked) prevents SW registration entirely in development |
| T-11-07 | Tampering | _rsc param creating duplicate precache entries | mitigate | precacheOptions.ignoreURLParametersMatching: [/^_rsc$/] strips the param before cache key lookup (D-03) |
| T-11-SC | Tampering | npm/pip/cargo installs | accept | @serwist/next and serwist audited [OK] in Plan 01; installed in Plan 01 before this plan runs |
</threat_model>
