<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /business/profiili RSC | Unauthenticated request must be redirected; no data returned |
| Client component → business_accounts UPDATE | RLS enforces auth.uid() = user_id; no cross-account write possible |
| changeLocaleAction Server Action | Sets httpOnly NEXT_LOCALE cookie; no user data written |
| signOut → sb-biz-* session | Only business cookies cleared; consumer session isolation maintained |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43p-01 | Information Disclosure | GET /business/profiili unauthenticated | mitigate | RSC guard: supabase.auth.getUser() returns null → redirect('/business/kirjaudu'); no data rendered before check |
| T-43p-02 | Elevation of Privilege | business_accounts UPDATE contact_phone | mitigate | RLS "Business updates own account" policy: auth.uid() = user_id enforced server-side; browser client cannot bypass; horizontal privilege escalation impossible |
| T-43p-03 | Elevation of Privilege | Session contamination on sign-out | mitigate | createBusinessBrowserClient().auth.signOut() uses sb-biz-* cookie prefix; consumer sb-* cookies untouched; verified from lib/supabase-business.ts cookieOptions |
| T-43p-04 | Tampering | contact_phone XSS injection | accept | React JSX escaping handles all output rendering; contact_phone is TEXT displayed via JSX, not innerHTML; no special mitigation needed |
| T-43p-05 | Information Disclosure | business_accounts row missing — edge case | mitigate | RSC: if (!account) redirect('/business'); page never renders with empty/undefined company data |
| T-43p-SC | Tampering | npm/npx installs | accept | No new npm packages in this plan; no package manager invocations |
</threat_model>
