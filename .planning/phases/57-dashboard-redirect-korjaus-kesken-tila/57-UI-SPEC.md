# Phase 57 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase makes no new visual primitives — it extends the existing `app/business/page.tsx` dashboard (`VenueRow`, `StatusCard`) with one new badge state ("Kesken") and one swapped CTA ("Jatka" replacing "Muokkaa" on Kesken rows). All values below are taken directly from the existing glassmorphism system documented in CLAUDE.md and the current `VenueRow`/`StatusCard` implementation — no new design system, no new component library, no new fonts.

| Destructive | `#dc2626` (`text-red-600`) / existing `bg-red-50 text-red-600` (rejected badge) | Unchanged — rejected status badge, not touched by this phase |

**New role — Kesken badge (neutral/gray):**

| Role | Value | Usage |
|------|-------|-------|
| Kesken badge background | `rgba(17,17,17,0.08)` (`bg-[rgba(17,17,17,0.08)]`) | Background of the new "Kesken" badge, replacing the amber Pending badge on rows where an `onboarding_draft` row exists |
| Kesken badge text | `rgba(17,17,17,0.55)` (`text-[rgba(17,17,17,0.55)]`) | Text of the "Kesken" badge |

Accent reserved for: venue name text (`text-[#111111]`), Jatka CTA button border/text (`border-[rgba(0,0,0,0.12)]` outlined pill, `text-[#111111]`) — no fill/solid accent buttons introduced in this phase.

This Kesken gray is a deliberate departure from the amber Pending badge (`bg-amber-100 text-amber-700`) specifically so the two statuses are visually distinguishable at a glance (per CONTEXT.md D-06): amber = "submitted, awaiting admin approval"; gray = "draft started, not yet submitted." It is not in the CLAUDE.md color table because it did not exist before this phase — it follows the existing badge structural pattern (`text-[10px] font-bold uppercase tracking-widest px-2 py-1 rounded-full`) with a new neutral fill, consistent with how `border-[rgba(0,0,0,0.12)]`/`rgba(17,17,17,0.45)` neutrals are already used elsewhere for "muted/secondary" semantics in this project.

## Interaction Notes (supplementary — not part of standard 6 dimensions, included for implementer clarity)

- **Badge precedence (D-04, D-05):** Status is one of four mutually exclusive values: `approved`, `pending`, `rejected`, `kesken`. When a `paikka_id` has a matching `onboarding_draft` row, the row renders the Kesken badge **instead of** the Pending badge — never both. Check for draft existence before falling into the existing `claim_status` ternary in `VenueRow` (line 110-122).
- **Action row on Kesken rows (D-08, D-09):**
  - "Muokkaa" button (line 135-140, links to `/business/{id}`) is **replaced** by "Jatka", linking to `/business/onboarding?paikka_id={paikka_id}` — reuses the already-implemented resume mechanism in `WizardInner.tsx`, no new routing logic.
  - "Esikatsele" button (line 127-134) is hidden or disabled on Kesken rows — venue is `published: false` at this stage, preview is not meaningful (D-09).
- **StatusCard unaffected (D-07):** No visual or logic change to `StatusCard` (lines 43-90). Kesken state is communicated only per-row, not via a top-level banner.
- **Layout impact:** Swapping badge color and button label does not change row height, padding, or flex structure — `VenueRow`'s existing `flex flex-col gap-1` / `flex items-center gap-3 mt-1` structure is preserved exactly; only the badge `className` ternary branch and the action button's `href`/label are conditional on Kesken state.
