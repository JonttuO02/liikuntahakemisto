## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → irreversible DELETE | The human gate is the only safeguard between a correct deletion and an unrecoverable mistake — there is no backup (D-03/D-07), so the boundary is the baseline-review approval. |
| migration runner → 5-table cascade | Applying the migration fires `ON DELETE CASCADE` across reviews, suosikit, business_paikka_links, onboarding_draft, business_branding. The boundary risk is the predicate matching a row it shouldn't (a claimed venue). |
| false-positive build → unverified push | A green build/typecheck does NOT prove the DB was changed (types come from config). The boundary is that verification must be the live post-deletion audit, not the build. |
