<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/business/analyze-website | Untrusted URL input crosses here |
| route.ts → external website (via scraper.ts) | Server initiates HTTP request to user-supplied URL — SSRF surface |
| route.ts → Supabase (business_branding) | Writes analysis results using service role key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-04-SSRF | Tampering | POST handler: new URL(url) + fetch | mitigate | Protocol whitelist (http:/https: only); hostname blocklist: localhost, 127.0.0.1, ::1, 192.168.*, 10.*, 169.254.169.254 — returns 400 before any fetch occurs. This is HIGH severity per security_enforcement |
| T-45-04-01 | Spoofing | POST handler JWT | mitigate | supabaseAdmin.auth.getUser(token) at route entry — same pattern as all business routes; service role key used for DB writes |
| T-45-04-02 | Elevation of Privilege | business_branding UPSERT | mitigate | UPSERT uses user.id from verified JWT as business_account_id — user can only write to their own row; service role bypasses RLS but identity is pre-verified |
| T-45-04-03 | DoS | POST: large HTML from external site | mitigate | AbortSignal.timeout(10000) in scraper.ts; htmlSnippet truncated to 8000 chars before Claude call; max 5 logo candidates |
| T-45-04-04 | Information Disclosure | GET handler | mitigate | GET uses same JWT verification — user can only read their own business_branding row (business_account_id = user.id filter in SELECT) |
| T-45-04-SC | Tampering | npm install (sharp, @vercel/functions) | mitigate | slopcheck completed in Plan 01; all packages [OK]; no postinstall scripts |
</threat_model>
