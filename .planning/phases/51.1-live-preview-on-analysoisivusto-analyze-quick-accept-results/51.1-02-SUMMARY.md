**Wrapped AnalysoiSivusto's preview phase in its own LivePreviewProvider instance with the WizardInner desktop split / mobile toggle layout, syncing logo and gallery picks into the live CalloutCard/DiagonaalKortti preview via SET_MEDIA effects while colors flow through a brandingData override.**

## Accomplishments
- `AnalysoiSivustoProps` widened with `paikkaInfo: PaikkaBase | null`; component now accepts and forwards it to a scoped `LivePreviewProvider`
- New `PreviewPhaseContent` inner component renders inside the provider, calling `useLivePreview()` for `dispatch` while all actual pickers/handlers/state remain owned by the parent `AnalysoiSivusto`

- Preview phase now renders the exact `WizardInner.tsx` split-view/toggle skeleton: desktop sticky `w-[360px]` sidebar with `LivePreviewPane`, mobile `LivePreviewToggle` swapping between pickers and `LivePreviewPane`
- Color picks (`bgColor`/`accentColor`) feed the preview live via the `brandingData` override prop — the same merge shape already used at the existing `onConfirm` call
- The five non-preview phases (`checking`, `url-input`, `analyzing`, `error`, `timeout`) are unchanged, still rendering inside the original `glass rounded-2xl p-6 w-full max-w-xl mx-auto` single-column wrapper
- `npx tsc --noEmit` reports zero errors across `AnalysoiSivusto.tsx` and `page.tsx` — the cross-plan `paikkaInfo` error flagged by Plan 01 is now resolved

## Decisions Made
- Combined Task 2 and Task 3 into a single commit for the reasons above (component definition without its render-tree wiring is unverifiable dead code).
- Used the effect-driven `SET_MEDIA` sync approach (the plan's preferred option) over wrapping `selectLogo`/`toggleGalleryImage` — simpler, uniform across initial seed and every pick, and required no changes to existing handler signatures or return contracts.
- Moved the `preview` branch to an early `return` before the `glass max-w-xl` wrapper (rather than conditionally stripping `max-w-xl` from the same wrapper) — this keeps the five non-preview branches' JSX completely untouched and gives the split layout unconstrained width, matching `WizardInner.tsx`'s structure exactly.
- Added `setCustomHexError` to `PreviewPhaseContent`'s props (the plan's prop list under Task 2 omitted it, but the existing `handleCustomHexSubmit`-adjacent `onChange` handler for the custom-hex input calls it) — this is a Rule 1 bug fix caught by `tsc --noEmit`, not a scope expansion: the prop was always needed for the moved JSX to compile.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Added missing `setCustomHexError` prop to PreviewPhaseContent**
- **Found during:** Task 3 (wiring PreviewPhaseContent into the render tree)
- **Issue:** The plan's Task 2 prop list for `PreviewPhaseContent` did not include `setCustomHexError`, but the moved custom-hex `<input>`'s `onChange` handler calls `setCustomHexError(null)` to clear a prior validation error as the user types. Without the prop, `tsc --noEmit` failed with `Cannot find name 'setCustomHexError'`.
- **Fix:** Added `setCustomHexError: (value: string | null) => void` to the props interface, destructured it in the function body, and passed `setCustomHexError={setCustomHexError}` at the `<PreviewPhaseContent>` call site in `AnalysoiSivusto`.
- **Files modified:** `app/business/onboarding/AnalysoiSivusto.tsx`
- **Verification:** `npx tsc --noEmit -p tsconfig.json` reports zero errors in the file after the fix.
- **Committed in:** `1d43605` (Task 2+3 commit)
