<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon client → business_accounts | Unauthenticated or wrong-user reads blocked by RLS SELECT USING |
| authenticated user → other business's links | Cross-business read blocked by RLS SELECT USING (auth.uid() = business_account_id) |
| INSERT to business_paikka_links | Only the business that owns the account can link a venue |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Information Disclosure | business_accounts SELECT | mitigate | RLS USING (auth.uid() = user_id) — anon and other authenticated users receive 0 rows |
| T-31-02 | Information Disclosure | business_paikka_links SELECT | mitigate | RLS USING (auth.uid() = business_account_id) — only the owning business can read its venue links |
| T-31-03 | Tampering | business_paikka_links INSERT/UPDATE | mitigate | WITH CHECK (auth.uid() = business_account_id) prevents a business from claiming venues for another account |
| T-31-04 | Elevation of Privilege | business_accounts UPDATE | mitigate | UPDATE policy WITH CHECK (auth.uid() = user_id) blocks writes to other accounts; approval_status can be changed by the business, but Phase 35 will restrict this column via a dedicated server-side handler |
| T-31-SC | Tampering | npm/pip installs | accept | No npm installs in this plan — SQL only |
</threat_model>
