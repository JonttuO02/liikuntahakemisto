   CREATE OR REPLACE FUNCTION storage.business_owns_paikka(p_business_id uuid, p_paikka_id text) RETURNS boolean
   LANGUAGE plpgsql SECURITY DEFINER SET search_path = public
   AS $$ BEGIN RETURN EXISTS (SELECT 1 FROM business_paikka_links WHERE business_account_id = p_business_id AND paikka_id = p_paikka_id::bigint); END; $$;

   CREATE POLICY "Business INSERT own folder" ON storage.objects FOR INSERT TO authenticated

     bucket_id = 'business-media'

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated user → Storage objects | Write policies gate on top-level path = auth.uid() |
| Storage policy → business_paikka_links | Ownership JOIN executed via SECURITY DEFINER to avoid RLS cascade |
| User → profiles.is_admin | Column updatable by any authenticated user via existing profiles UPDATE policy (residual risk — mitigated operationally by service-role-only set in SQL Editor; structural fix in Phase 35) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-05 | Tampering | Storage INSERT/UPDATE — cross-business path write | mitigate | (storage.foldername(objects.name))[1] = (auth.uid())::text blocks writes outside own top-level folder |
| T-31-06 | Tampering | Storage INSERT/UPDATE — invalid paikka_id in image path | mitigate | storage.business_owns_paikka() checks business_paikka_links for a matching row; cast failure on non-numeric foldername[2] returns exception (deny-by-exception) |
| T-31-07 | Spoofing | RLS bypass via inline JOIN in Storage policy | mitigate | SECURITY DEFINER function with SET search_path = public executes outside RLS context of business_paikka_links, preventing silent cascade failure |
| T-31-08 | Elevation of Privilege | profiles.is_admin self-elevation | accept (partial) | Existing UPDATE policy allows any authenticated user to set is_admin=true on their own row. Operationally mitigated: is_admin=true is only set via SQL Editor (service role). Phase 35 will add a WITH CHECK clause to block self-elevation structurally. Accepted as low risk for v1.7 given internal-only admin UI. |
| T-31-09 | Tampering | sync-paikat overwriting managed venues | mitigate | Plan 03 adds pre-filter in TypeScript that excludes business_managed=true place_ids before the upsert batch |
| T-31-SC | Tampering | npm/pip installs | accept | No npm installs in this plan — SQL and directory creation only |
</threat_model>
