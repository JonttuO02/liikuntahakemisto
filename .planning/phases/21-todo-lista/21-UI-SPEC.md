## Typography

| Role | Size | Weight | Line Height | Class |
|------|------|--------|-------------|-------|
| Micro / badge | 10px | 700 (bold) | — | `text-[10px] font-bold uppercase tracking-widest` |
| Body / UI label | 14px (text-sm) | 400 or 700 | 1.5 | `text-sm` / `text-sm font-bold` |

TO DO -lista page heading: `font-serif text-2xl font-bold text-[#111111]` — "TO DO -lista".
Empty/unauthenticated state heading: `font-serif text-2xl font-bold text-[#111111] text-center`.
Body copy in empty states: `text-sm text-[rgba(17,17,17,0.45)] text-center max-w-xs`.

└── px-4 py-8 max-w-2xl mx-auto

    │   "TO DO -lista"
    ├── ul: flex flex-col gap-3
    │   └── li (per place): flex flex-row items-start gap-2
    │       ├── div.flex-1.min-w-0

## Interaction: Optimistic Delete

1. User taps remove button.
2. Item is removed from `paikat[]` state immediately (optimistic).
3. `supabase.from('suosikit').delete().eq('user_id', userId).eq('paikka_id', paikkaId)` fires in background.
4. Success: no-op.
5. Error: `console.error('[SuosikitClient] delete error:', error)` — item is restored to `paikat[]` (rollback to previous state).
6. No toast, no confirmation dialog.

Gate: `removeTodo` must check `userId !== null` before firing. `userId` is populated by `subscribeToAuthUser` — replicate the existing guard pattern from `HeartButton.tsx`.

Source: CONTEXT.md D-09; RESEARCH.md Pattern 1, Pitfall 4.

## API Payload Key Decision

`/api/saasuositus` route receives `body.suosikit` (internal key). This key is NOT changed.
`Etusivu.tsx` internal variable `suosakkiNimet` → `todoNimet` (code-level rename only).
The JSON key sent over the wire stays `suosikit`.

Rationale: Internal API with no external consumers. Renaming provides no user-visible benefit and requires two-file atomic update with no gain.

Source: CONTEXT.md D-06; RESEARCH.md Pattern 4, Assumption A3.
