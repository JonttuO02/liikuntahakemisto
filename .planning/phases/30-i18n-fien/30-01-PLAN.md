<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP cookie → server | NEXT_LOCALE cookie value arrives from browser on every request; must be validated before use |
| Server Action input | changeLocaleAction receives locale string from client button click; must be typed to 'fi' \| 'en' |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Tampering | i18n/request.ts — dynamic import path construction | mitigate | resolveLocale() whitelist validation prevents path traversal via malformed NEXT_LOCALE cookie; only 'fi' or 'en' pass through to dynamic import |
| T-30-02 | Tampering | changeLocaleAction — locale parameter | mitigate | TypeScript type `'fi' \| 'en'` enforced at server action boundary; invalid strings rejected by type system at call site |
| T-30-03 | Tampering | NEXT_LOCALE cookie — session hijack | accept | Cookie controls UI language display only, not auth or access control; no PII involved; risk is cosmetic (wrong language shown) |
| T-30-SC | Tampering | npm install next-intl | mitigate | Package Legitimacy Audit in RESEARCH.md: next-intl [OK], 5.5 yrs on npm, 2M+/wk downloads, slopcheck passed |
</threat_model>
