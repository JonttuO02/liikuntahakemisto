## Integration Check Summary

### Blockers (1)

**BLOCKER-1: Wizard step skip via URL — ONBOARD-01**

`OnboardingWizardInner.tsx` renders any step 1–6 based on the URL `?step=N` parameter with no sequential enforcement. The ProgressBar UI prevents clicking forward past `completedSteps[]`, but direct URL navigation bypasses this. A user can navigate to `?step=5` without completing steps 2–4. The `save-step` route has no analogous guard and will accept step data in any order. If a user skips to step 6 and submits, null values are written to `liikuntapaikat`.

- File: `app/business/onboarding/OnboardingWizardInner.tsx`
- Fix: add `if (step > (draft?.current_step ?? 0) + 1) { goToStep(draft?.current_step ?? 1); return; }` guard on step render

### API Bug (1)

**BUG: update-paikka blocks edits for pending/rejected venues — BIZPANEL-02**

Showing "Muokkaa" for all `claim_status` values is **intended behavior** — businesses should be able to edit their venue data while waiting for approval or after rejection. However, `POST /api/business/update-paikka` has an ownership check that requires `claim_status='approved'` and returns HTTP 403 for pending and rejected venues, silently blocking the intended edit flow.

- File: `app/api/business/update-paikka/route.ts` (ownership check, ~line 40–53)
- Fix: remove or loosen the `claim_status='approved'` restriction so all linked venues (pending, approved, rejected) can be saved via this route
